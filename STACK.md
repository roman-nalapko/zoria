# Здача "Зорі": стек учасника

Цей стек дописала команда `npx zaria-kit init stack` навколо того, що у вас
уже було. Він виконує ворота допуску частини 4 - P4-01 ... P4-04 і
P4-10 ... P4-11 - і далі змінюється як завгодно: черга, кеш, база, другий
сервіс, своя голова. Оцінюється ваш код, а не вірність шаблону.

## Що дописано

| Шлях                          | Що це                                                                  |
| ----------------------------- | ---------------------------------------------------------------------- |
| `compose.yaml`                | стек здачі: голова, службові ручки, штаб; ролі - мітками               |
| `bot/Dockerfile`              | образ голови: `npm ci`, збірка, запуск командою з `zaria.bot`          |
| `control-plane/`              | службові ручки бота без жодної залежності                              |
| `.npmrc`                      | реєстр конкурсу і посилання на `ZORIA_NPM_AUTH`; секрету у файлі немає |
| `.dockerignore`, `.gitignore` | що не їде в контекст збірки і в репозиторій                            |

Каталог штабу (`zaria-kit init hq`) отримує свій `Dockerfile` і `serve.mjs`,
а стек - сервіс `hq` з міткою `zaria.hq`. Штабу немає - сервісу немає, і
ступінь `hq-bundle` прогону просто не йде: партіям це не заважає, але
двадцять балів осі штабу стануть нулем на прийманні. Завели штаб пізніше
за стек - покличте `npx zaria-kit init stack --force`, і сервіс допишеться.

## Далі

```sh
cd bot && npm install && cd ..   # lockfile обов'язковий (02-build.md, 4.4)
npm install                          # кит у корені: npx zaria-kit знайде його тут
npx zaria-kit preflight              # ті самі одинадцять ступенів, що в нас
```

Потрібні Docker з compose v2 і Node.js 24. `preflight` збере образи, підніме
стек, зіграє коротку партію проби і запише вердикт у `preflight.json`.
Секрет реєстру береться зі змінної `ZORIA_NPM_AUTH` вашого оточення і в
образ не потрапляє.

Штаб збирається своєю командою - якщо він у вас є, `npm install` потрібен і
в його каталозі.

## Ролі і мітки

Конвеєр читає стек мітками, а не іменами сервісів:

| Мітка                   | На чому стоїть    | Що означає                                                    |
| ----------------------- | ----------------- | ------------------------------------------------------------- |
| `zaria.role: head`      | рівно один сервіс | голова на проводі: їй вузол кладе `ZARIA_URL` і `ZARIA_TOKEN` |
| `zaria.control: <порт>` | не більше одного  | службові ручки; без мітки - голова, порт 7801                 |
| `zaria.hq: <порт>`      | не більше одного  | штаб: віддає зібрану сторінку                                 |
| `zaria.belief: <шлях>`  | на голові         | абсолютний шлях щоденника віри всередині контейнера           |

Сервісів може бути скільки завгодно, хоч один на всі ролі. Правила машини
(без `privileged`, чужих мереж і просторів імен, без bind-томів, без
`include` і `extends`) - `02-build.md`, розділ 3.

## Шов двох площин

Голова - площина даних: у ній провід і такт, і більше нічого. Службові
ручки - площина керування: усе, що питають ззовні. Голова віддає їм знімок
своїм внутрішнім портом (`STATUS_PORT`, мережа `plane`, назовні не
публікується), а щоденник віри вони читають зі спільного тому.

Заради чого шов: голова догравує партію, навіть якщо площину керування
перезапустили; передплатники `belief-stream` живуть не в петлі такту; `/health`
і `/metrics` коштують голові однієї відповіді внутрішнього порту. Ціна -
зайвий хоп і таймаут (`HEAD_TIMEOUT_MS`, 1000 мс): голова не відповіла -
503 з причиною.

Злити обидві площини в один процес можна: тоді стан читається з пам'яті без
хопа, але рестарт керування валить провід.

## Підняти руками

Стек піднімається під вузлом: адреса і печатка приходять голові змінними.

```sh
ZARIA_URL=ws://... ZARIA_TOKEN=... docker compose up --build
curl -s localhost:7801/health
curl -s localhost:7801/metrics
curl -sN localhost:7801/belief-stream | head -3
```

Штаб - `http://localhost:8180/`. Порти змінюються змінними
`ZARIA_CONTROL_PORT` і `ZARIA_HQ_PORT`, адреса публікації - `ZARIA_BIND`
(за замовчуванням `127.0.0.1`). Без адреси вузла голова стає в простій, і
`/health` чесно відповідає 503.

Локальний пакет із трьох партій і далі грається без стека, просто в
каталозі бота: `npm run play -- --fast`.

## Змінні

| Сервіс | Змінна                          | За замовчуванням             | Що означає                                       |
| ------ | ------------------------------- | ---------------------------- | ------------------------------------------------ |
| голова | `ZARIA_URL`, `ZARIA_TOKEN`      | порожньо                     | адреса вузла і печатка місця; їх кладе прогін    |
| голова | `ZARIA_ENGINE`                  | порожньо                     | хеш рушія, якого голова вимагає від вузла        |
| голова | `ZARIA_PRESET`                  | `рівний`                     | архетип заглушки на старті                       |
| голова | `ZARIA_FREEZE`                  | порожньо                     | `1` - здачу заморожено, промоут відмовляє        |
| голова | `ZARIA_BELIEF`                  | `/data/belief.ndjson`        | щоденник віри; він же в мітці `zaria.belief`     |
| голова | `STATUS_PORT`, `STATUS_HOST`    | 7811, `0.0.0.0`              | внутрішній порт стану                            |
| ручки  | `PORT`, `HOST`                  | 7801, `0.0.0.0`              | службовий контракт; слухати треба всі інтерфейси |
| ручки  | `HEAD_URL`, `HEAD_TIMEOUT_MS`   | `http://head:7811`, 1000     | де голова і скільки її чекати                    |
| ручки  | `ZARIA_BELIEF`, `TAIL_MS`       | `/data/belief.ndjson`, 100   | чий хвіст віддавати і як часто опитувати         |
| штаб   | `HQ_PORT`, `HQ_HOST`, `HQ_ROOT` | 8080, `0.0.0.0`, `/app/show` | сервер зібраного показу                          |

Секретів у репозиторії не має бути зовсім: усе, що потрібно збірці і
партії, приходить змінними оточення (`02-build.md`, 6.5).
